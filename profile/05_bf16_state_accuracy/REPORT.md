# 05：跨 chunk BF16 状态保存精度验证

## 验证问题

官方 Numerical Precision 说明：K2 用 FP32 FMA 更新状态，在更新之间保存 BF16，其内部推理 benchmark 未测到准确率损失。这里的更新是每个 CHUNK=16 的块更新，状态在 shared memory 中跨 chunk 保存。

本实验固定其他计算精度，比较 BF16 状态保存与 FP32 主状态保存的算子输出、最终状态差异。实验不包含真实模型任务评测，也不把 FP32 主状态路径当作数学真值。

## 两条计算路径

复用原 harness，真实 K1 为每组输入产生 kd、qd、kr、gt、inv、mqk，真实 K2 给出对齐目标。两条 PyTorch 路径共用同一份 K1 workspace、v、beta 和 BF16 初始状态：

R=(V−Kd·S)⊙sigmoid(beta)，U=INV·R，Y=Qd·S+Mqk·U，S_new=GT⊙S+Krᵀ·U。

保留原有各中间步骤的 BF16 舍入、近似 sigmoid 和 K1 内的 FP16 求逆。两条路径都以 BF16 状态操作数执行 GEMM，状态增量以 FP32 累加，更新使用 FP32 FMA。

- BF16 路径：每个 chunk 更新后转 BF16，供下个 chunk 使用。
- FP32 主状态路径：更新后保留 FP32；GEMM 使用临时 BF16 副本，不覆盖主状态。

每组都要求 BF16 microbench 的全部输出和最终状态与真实 kernel 逐元素相等。不直接使用 API 的 FP32 state dtype 作为对照，因为 kernel 内部仍转成 BF16。

## 公共输入与控制变量

固定 N=1、T=8192、H=96、D=128、CHUNK=16，每条状态链更新 512 次。固定 A_log=dt_bias=0、lower_bound=-5、输出 scale=1/sqrt(128)。

每个 seed 按相同顺序生成以下随机张量，再对扫描变量进行覆盖。所有组 seed 为 0–4：

| 输入 | 采样方式 |
|---|---|
| q、k | 标准正态，转 BF16；真实 K1 内做 L2 归一化 |
| v | 正态，标准差 0.125，转 BF16 |
| beta logit | 标准正态，转 BF16 |
| gate logit | 标准正态，转 BF16 |
| S₀ | 正态，标准差 0.02，转 BF16，外部布局 [V,K] |

标准差不是硬上下界。这些是公开的合成采样分布，不宣称代表真实模型。q/k/v/S₀ 的变化由多 seed 随机背景覆盖，不另外扫描它们。同一个 seed 在所有组具有完全相同的 q/k/v/S₀，C 组还保留相同的随机 beta。

## A/B/C 实验组

| 组 | 改变的变量 | 固定的变量 | 数量 |
|---|---|---|---:|
| A 随机基线 | 所有输入按上述分布随机采样 | 公共参数 | 5 |
| B beta 扫描 | beta logit=-9、-7、-5、-3、-1、0、2 | chunk gate 目标 0.9999；每个 seed 的 q/k/v/S₀ 不变 | 35 |
| C gate 扫描 | chunk gate 目标 0.5、0.9、0.99、0.999、0.9999 | 每个 seed 的 q/k/v/S₀ 和随机 beta 不变 | 25 |

合计 65 组完整 8192 token 检查。B 的 beta 在整个序列、所有 head 上使用同一指定 logit。C 的 gate 在整个序列、所有 head 和通道上使用同一指定 logit。扫描变量改变后重新执行真实 K1，不手工篡改中间结果。

对于目标 chunk 保留系数 r，令 p=−ln(r)/(5×16)，gate 输入 logit=ln(p/(1−p))。真实系数受 BF16 输入量化、近似 sigmoid 和指数计算影响，因此同时记录实际 GT 均值。B 表中参数是激活前 beta logit，实际系数记录为 K2 的近似 sigmoid 后 BF16 值的均值。

A 回答随机输入下差异有多大；B 在同一弱衰减背景下隔离 beta 的影响；C 在同一随机 beta 背景下隔离 gate 的影响。B 与 C 是两条条件扫描，不是完整的 beta×gate 网格，不据此推断任意交互条件。

## 指标与结果

主要指标为全序列输出相对 L2、末尾 1024 token 输出相对 L2、输出最大绝对差异，以及最终状态差异。误差统计使用 FP64，分母为 FP32 主状态路径参考范数。最终状态也提供统一 BF16 格式后的比较，该转换不参与递推。

非零更新丢失比例仅作为原 harness 的辅助诊断保留，不用于衡量准确性或判断通过。没有预设任意误差阈值；零差异仅代表这组输入下没有观察到差异。

[RESULTS.md](RESULTS.md) 汇总所有 seed 的范围和图；[analysis/DATA.md](analysis/DATA.md) 保存完整原始结果。结论仅适用于本次采样、参数和序列长度，不能等同于数学误差或模型准确率损失。

## 本次结果与解释

65 组均完成，原 kernel 与 BF16 microbench 的全部输出、最终状态最大绝对差异均为 0，所有结果有限。

- A：5 个随机 seed 的输出差异均为 0，最终状态统一 BF16 格式后差异也为 0。随机 gate 的实际平均 chunk 保留系数约为 1.37×10⁻¹⁴，不能把这个结果外推为所有正常模型输入都无误差。
- B：固定 chunk gate≈0.9999，beta logit 从 −9 到 2 扫描。全序列输出最大差异在 logit=−7 时达到 4.6002%，末尾窗口为 7.5171%，统一格式后的最终状态为 8.0049%。logit=−9 的输出最大差异为 3.4617%，−5 为 2.4344%，0 为 0.7168%。差异不是随 beta 减小而严格单调增加。
- C：固定每个 seed 的随机 beta，gate 目标从 0.5 增加到 0.9999，输出最大差异依次为 0.2900%、0.5112%、0.7079%、0.7532%、0.7586%。本次扫描中，显式衰减减弱伴随更大的保存策略差异。

这些结果来自统一的 S₀ 标准差 0.02，没有沿用旧场景 3 的 S₀ 标准差 1。旧报告的 14.55% 不属于这次设计，已由新结果覆盖。新 B 组说明即使不增大初始状态，弱衰减背景下的小 beta 也可能对应明显的两路径差异；不据此推断真实模型频率或任务损失。
